## Ranked initial work

First consolidate profile startup language, remove the unused chrome API, and reuse the existing session opacity helper. Each is narrow, reversible, and can be checked without changing persisted behavior. Repair the three pre-existing test failures next, preserving their intended coverage.

Security dependency findings need urgent triage. The two critical transitive packages are shell-quote and tar. Inspect dependency paths and advisories before a scoped lockfile update. Do not run audit fix --force. Expo-compatible patch alignment precedes any SDK-major migration.

The startup-language copies in both profile routes match lib/i18n/startup-language.ts. LoadingScreen additionally checks browser language and must retain that behavior. Juz lookup copies differ on missing matches, so a shared helper needs explicit nullable-versus-fallback policy.

The tafsir import/select transactions in settings and ReadingSettingsSheet match. AyahDetailModal additionally refreshes its local state, so it cannot be folded into the same transaction without an explicit callback contract.

## Tool findings need triage

`analysis-summary.json` retains all 31 measured clone groups and Knip output. A scanner match is not permission to delete code. Platform files, Expo routes, generated require maps, side effects and runtime assets need native/web-aware checks. The current dependency graph favors web resolution, so a second native graph is a planned task.

All high-risk changes require a bounded follow-up task, characterization tests and primary-engineer integration. The executable backlog distinguishes ready tasks from tasks still needing this preparation. Completion requires final architecture and behavioral review, not a zero scanner percentage obtained by exclusions.
