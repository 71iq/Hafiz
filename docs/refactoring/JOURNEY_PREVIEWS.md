# Journey ayah preview characterization

RF-061 adds regression coverage for the existing JourneyAyahCard. It leaves production source unchanged. The route in app/(tabs)/reflection-journey.tsx already sends all four supported preview block types to this one owner.

Keep the two inline row presentations. Their shared prefix contains a Pressable, a reference label and a callback into the same detail-target state. Their children have different font and content rules. A children wrapper would forward that state and reference without owning an independent rule. Card already owns the surrounding presentation, and AyahDetailModal already owns the detail interaction. No new component, hook or dependency is justified by this clone match.

The new tests render the real owner, Card, localization helper, string catalog and translation-language catalog through the installed React Native test renderer. They use a controlled settings snapshot and I18nManager value, a manual animation-frame queue, and substitutes for the database, font-loader boundary and detail modal. Synthetic glyph tokens and text are fixtures, not Quran inputs. No database writes or remote requests are permitted.

The 36 cases cover both UI languages, default and active translation tables, explicit and settings-selected tafsir, qcf2/v4/v4-tajweed font arguments, cached and pending pages, page deduplication, marker palette arguments, loading states, fallback titles, literal Unicode and whitespace, row target/tab/close wiring, shared row classes and pressed scale, query/font failures, late query results and completion after unmount. The queries retain parameter arrays and ordered selection. A pending font that resolves after unmount must not queue a readiness frame.

Primary preparation passed 36 focused cases, strict types, zero-warning lint and formatting of the new test. Four temporary mutations produced 14 wrong-target, eight missing-font-wait, two wrong-translation-direction and four ignored-explicit-source failures. The original owner was then restored byte for byte and all 36 cases passed again. The cold suite passed 86 suites and 875 tests without skips.

Evidence is preserved under .refactor-baseline/rf061-journey-preview-v1/. readiness.json names the final artifacts and preflight logs. The task requires fresh controller commands, a separate stronger review and primary acceptance. Preparation alone does not complete it.

This is characterization, not a production refactor or a measured performance improvement. The app, existing tests, protected text/fonts/data/mappings, dependencies and runner settings remain frozen. No duplication reduction or new clean Knip/audit result is claimed.

These fixtures do not execute real SQLite, page-font loading, browser layout, native devices, full journey persistence or the actual detail modal. They verify the target/tab callback contract only. The unchanged modal retains copying and sharing; actual Unicode copying is not exercised here. The existing font-rejection fallback remains, and this task does not add cancellation for an animation frame that was already queued before cleanup. Browser/theme/geometry and device checks are not repeated because no production code changes.
