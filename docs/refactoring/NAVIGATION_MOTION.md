# Navigation motion audit

RF110 is a local source audit and implementation plan. It changes no application code and certifies no browser or native behavior. RF103 still owns completion of the navigation motion work. Findings refer to the modernization checkout, not the original checkout and its separate AppNavigation edit.

## Current owners

`components/ui/AppNavigation.tsx` owns three timed behaviors. `BottomTabItem` springs its scale to 0.98 on press-in and 1 on press-out, with damping 15 and stiffness 400. It passes navigation callbacks through unchanged. `BottomBar` times a hidden value to 0 or 1 over 200 ms based on `visible && !immersive`; its style derives translation by 120 px and opacity by 1 minus hidden. Pointer events follow the boolean immediately. `FloatingPanel` times progress to 1 or 0 over 180 ms. Its style combines opacity with an LTR offset of -24 px or RTL offset of 24 px. It also owns a separate 180 ms hover/blur hide timer. That interaction delay is not the animation duration, even though the numbers match.

`SidebarItem` uses immediate pressed scale 0.96. `SidebarProfileCard` uses immediate pressed opacity 0.76. These are separate feedback decisions, not timed Reanimated work. `PersistentSidebar` has no timed transition in this owner. Keep their feedback and account/profile behavior outside the three motion repairs.

`AppNavigation` chooses bottom navigation below the shared sidebar breakpoint of 768 px, a floating panel at 768 through 1023 px, and a persistent sidebar at 1024 px and above. Mushaf at widths of at least 768 px returns null before choosing a sidebar. Immersive mode hides the floating and persistent sidebars; the bottom bar combines immersive with chrome visibility. `app/(tabs)/_layout.tsx` composes the navigation through the Tabs tabBar callback and supplies RTL. Preserve these branches, routing and viewport contracts.

## Installed preference and cancellation behavior

Installed react-native-reanimated is 4.2.1. Its `src/hook/useReducedMotion.ts` captures the system preference at module evaluation and documents that changes do not rerender consumers. `src/ReducedMotion.ts` initializes a JS value and UI shared value from a system snapshot. Its setter can update that manager. `src/component/ReducedMotionConfig.tsx` can set a configuration and restore it during cleanup. No usage of that component or direct manager mutation was found in app, components or lib during this audit. This is a source observation, not a runtime reproduction.

`src/animation/util.ts` resolves an absent config or ReduceMotion.System through the UI manager. Explicit ReduceMotion.Always returns true and Never returns false. Both ReduceMotion and cancelAnimation are public exports in `src/index.ts`. Relying only on the library hook or default System does not supply the app's existing live subscription. A startup reduced snapshot can also conflict with a later live opt-in if an allowed branch retains the default System configuration.

`src/valueSetter.ts` cancels a previous animation before processing an assigned target or new animation. `src/animation/util.ts` implements cancellation through assigning the current value and documents asynchronous cancellation. A future repair should set the desired shared-value endpoint under reduced/unknown preference and use the existing `lib/ui/reduced-motion.ts` subscription. It should explicitly use ReduceMotion.Never only in the allowed branch so the shared live preference owns that choice. Do not mutate the global ReducedMotionManager or add a global config component for this repair. Do not claim synchronous native UI-thread cancellation from this source audit. Actual browser and supported native checks must assess timing and focus independently.

## Three bounded implementation scopes

1. BottomTabItem press feedback. Change only its imports, local preference/pressed-target ownership and press handlers/effect. Keep a ref for the currently requested pressed endpoint if needed so a live change snaps to 0.98 while pressed or 1 while released. Unknown and reduced motion keep immediate pressed feedback; allowed motion retains the exact spring with explicit Never. Preserve spring handoff while allowed. Do not remove feedback, change navigation/long-press callbacks, labels, selected state, colors, sizes or descriptor typing. Verify press-in/out, mid-spring reduction, opt-in, rapid reversals, unmount and callback counts through the actual exported AppNavigation composition.
2. BottomBar visibility. Change only its shared preference read and timing effect. Snap the existing hidden value to the current chrome target under reduced/unknown; keep the 200 ms allowed timing with explicit Never. Preserve pointer events, safe-area position, backgrounds, routing and event prevention. Verify visible/hidden/immersive changes, live preference and interrupted target reversal without stale opacity/translation. Use the real ChromeProvider, both locales, phone widths and cold starts under both media values.
3. FloatingPanel progress. Change only its shared preference read and animation effect. Snap to the current open endpoint under reduced/unknown; retain the 180 ms timing with explicit Never when allowed. Keep the distinct hover/blur hide delay, cancellation and cleanup, focus, trigger/edge hover, click toggle, immersive close, navigation close and RTL offset. Verify at widths within 768 through 1023, including hover re-entry during a pending hide and preference changes during entry/exit. Preserve the absence of a floating panel at 1024 and the wide Mushaf branch.

Keep each implementation independently scoped, tested, evaluated and accepted. These are prepared designs, not approved source tasks yet. Inspect current source again before freezing exact artifacts. Do not change AppNavigation broadly or format unrelated code just to install a small repair. A whole-owner reversal and unchanged-input hashes should protect the other owners while each slice runs.
