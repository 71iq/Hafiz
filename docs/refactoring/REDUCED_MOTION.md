Button, ToggleGroup, EmptyState, ErrorBoundary and several navigation controls use instantaneous pressed scale feedback. They have no timed animation in that feedback. RF103 must decide which feedback needs adjustment and retain a visible pressed state. The new ReadingStepper uses the existing instantaneous sheet feedback outside the original shared-UI inventory. RF103 must account for that actual caller before declaring the inventory complete. The global CSS background transition is an autofill workaround, not a loading or navigation animation. No CSS change is included.

The installed Reanimated useReducedMotion hook reads the app-start preference and does not rerender on changes. It cannot own this live preference. The installed RN Web AccessibilityInfo adapter keys event handlers by their string representation. One shared observer avoids collisions between repeated identical placeholder callbacks. RF038 introduced lib/ui/reduced-motion.ts as the shared live system-preference hook. useSyncExternalStore supplies the installed React subscription contract and conservative server snapshot.

## Remaining shared loading indicators

The final RF103 source scan found two repeating indicators outside the earlier transition list. RF103 covers their shared BusyIndicator policy. `components/ui/SyncIndicator.tsx` shows an 8px ActivityIndicator while syncing. `components/ui/ConfirmDialog.tsx` shows a small white ActivityIndicator while confirmation is loading. Both use BusyIndicator, which reuses the live preference and shows a static LoaderCircle under unknown/reduced motion. Allowed motion retains the original ActivityIndicator size and color. The callers keep their sync status, dialog loading, callbacks and disabled states. Backlog and PROGRESS.md own acceptance status.

A direct `animating={false}` change is insufficient for the cross-platform contract. Installed React Native Web pauses its SVG rotation and can retain visibility with `hidesWhenStopped={false}`. Installed Android ProgressBarContainerView instead makes a non-animating indicator invisible. This is installed-source evidence, not native execution. The shared static branch avoids that visibility difference. Numeric sync size stays 8px; the small dialog indicator stays 20px, matching the installed React Native and React Native Web sizing. Preparation and runtime evidence are recorded in `.refactor-baseline/rf103-shared-busy-motion-v1/`. Native/device execution remains unverified.

Primary retains the existing immediate press-state feedback in Button, ToggleGroup, EmptyState, ErrorBoundary, SidebarItem, SidebarProfileCard and both actual ReadingStepper callers. Their style callbacks assign scale, opacity or background endpoints without interpolation or repetition. ReadingStepper is used as a pill in Settings and a sheet in ReadingSettingsSheet. This decision adds no preference observer or behavior change. RF048 still owns broader accessibility, contrast and touch verification. This inventory does not certify feature-local loading indicators or app-wide motion behavior.

RF103 accounts for the accepted Skeleton, Switch, OfflineBanner, Toast, Sheet, DropdownMenu, ResponsiveOverlay and all three AppNavigation timed owners through their own controller runs and primary receipts. BusyIndicator completes the two additional shared progress callers. The immediate-feedback source decision above remains unchanged.
