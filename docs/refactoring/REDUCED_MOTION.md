# Reduced motion inventory

RF038 covers the system preference and the repeating Skeleton pulse. The shared API starts with motion disabled, queries the existing React Native AccessibilityInfo API and observes live changes through one reference-counted listener. React Native Web supplies the browser media-query implementation. A late initial query cannot overwrite a newer event. The last unsubscribe removes the listener, invalidates pending callbacks and restores the conservative unknown snapshot.

Skeleton keeps its existing loading shapes and theme colors. Reduced or unknown preference uses static opacity 0.5, including the first frame. An explicit no-preference retains the original 0.3 to 0.7 pulse and 1200 ms native-driver timing. No setting, database write, provider or dependency is added. Existing composed placeholders reuse the same lifecycle.

Button, ToggleGroup, EmptyState, ErrorBoundary and several navigation controls use instantaneous pressed scale feedback. They have no timed animation in that feedback. RF103 must decide which feedback needs adjustment and retain a visible pressed state. The new ReadingStepper uses the existing instantaneous sheet feedback outside the original shared-UI inventory. RF103 must account for that actual caller before declaring the inventory complete. The global CSS background transition is an autofill workaround, not a loading or navigation animation. No CSS change is included.

The installed Reanimated useReducedMotion hook reads the app-start preference and does not rerender on changes. It cannot own this live preference. The installed RN Web AccessibilityInfo adapter keys event handlers by their string representation. One shared observer avoids collisions between repeated identical placeholder callbacks. RF038 introduced lib/ui/reduced-motion.ts as the shared live system-preference hook. useSyncExternalStore supplies the installed React subscription contract and conservative server snapshot.

RF048 depends on both RF102 and RF103. Completing this Skeleton slice does not certify all animations, native runtime behavior or the final accessibility review. Native component tests mock the system API and animation scheduling. They do not replace device evidence. Browser checks use real Expo, NativeWind, settings providers and components through a temporary QA route gated by actual local SQLite readiness. They block remote requests and use browser media emulation. The QA route is removed after export and never committed or deployed.
