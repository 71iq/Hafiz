# Technology stack specification

Decision date 2026-10-15. Exact installed versions come from package-lock.json. `registry-versions.json` records the npm registry snapshot used for comparison. Latest does not imply compatible.

## Compatibility research

Expo's current reference lists SDK 55 with RN 0.83 and React 19.2.0, SDK 56 with RN 0.85, and SDK 57 with RN 0.86. The independent latest RN and React releases are not a valid Expo upgrade pair. Use Expo's supported dependency matrix and the SDK upgrade walkthrough for each step. [Expo SDK reference](https://docs.expo.dev/versions/latest/), [upgrade procedure](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/).

The registry snapshot reports Expo 57.0.29, RN 0.87.1, React 19.3.1 and TypeScript 7.0.2 as independent latest releases. It also reports dependency-cruiser 18.6.0 supporting TypeScript below 7. A blanket latest-version update would break the selected compatibility set. These versions are comparison evidence, not approved install targets.

TanStack Query documents React Native support and requires explicit native online/focus integration. Test NetInfo and AppState cleanup, background resumption and account changes before adding those listeners. Do not add another connectivity package because NetInfo already exists. [TanStack React Native guide](https://tanstack.com/query/latest/docs/framework/react/react-native).

NativeWind v4 is the installed stable major; its current site advertises v5 as a release candidate. Uniwind is a maintained alternative, but replacing the existing theme pipeline and CSS interop patch has no demonstrated payoff. [NativeWind installation](https://www.nativewind.dev/docs/getting-started/installation).

React Native Reusables and gluestack both offer native-capable components. Hafiz already owns shared controls and modal behavior, so importing another complete kit would create two systems and put RTL/focus/safe-area behavior at risk. Keep the existing components and extend specific gaps. [React Native Reusables](https://reactnativereusables.com/docs), [gluestack introduction](https://gluestack.io/ui/docs/home/overview/introduction).

See decisions/0001-preserve-expo-and-source-owned-ui.md for the consequential choice. Revisit a choice only with a concrete compatibility, behavior, maintenance or measurement need.

## Lint compatibility findings

The installed lint pair is ESLint 9.39.4 and eslint-config-expo 56.0.4. Expo's SDK 55 dependency check recommends eslint-config-expo ~55.0.1. An isolated install of 55.0.1 with the current ESLint version loaded the unchanged project config and reported zero errors and 71 warnings. It did not change the root manifest, lock or installed dependency tree. [Expo lint guide](https://docs.expo.dev/guides/using-eslint/), [SDK 55 preset changelog](https://github.com/expo/expo/blob/sdk-55/packages/eslint-config-expo/CHANGELOG.md).

That successful run does not justify adopting the older preset. It resolves react-hooks plugin 5.2.0 instead of the installed 7.1.1. Effective-config comparisons for `app/_layout.tsx`, `lib/settings/context.tsx`, the dependency security check and `tests/unit/theme-color-swatch.test.tsx` found nine active rules missing. These include set-state-in-render, static-components and error-boundaries. Evidence is `.refactor-baseline/lint-sdk55-preflight/preflight.json`. RF-008 must preserve current lint coverage or document a reviewed alternative before any preset change. No preset downgrade is approved.

ESLint 9 reached end of maintenance on 2026-08-06. RF-044 must split out a supported ESLint/preset/plugin compatibility task before individual warning fixes. Keep this debt visible while the supported dependency set is researched. Do not force incompatible peer dependencies, disable checks or buy commercial support through this mission. [ESLint version support](https://eslint.org/version-support/).

The 2026-10-16 maintenance check reports ESLint 10.12.0. Current stable eslint-plugin-react 7.37.5 and eslint-plugin-import 2.32.0 exclude ESLint 10 from their peer ranges. Expo preset 58.0.4 still depends on those plugin lines. This is a declared-support gap, not evidence of a runtime failure. RF-044 must research a compatible set before an upgrade; forcing peer resolution is not approved. The snapshot is .refactor-baseline/lint-maintenance-registry.json. [ESLint metadata](https://registry.npmjs.org/eslint/10.12.0), [React plugin metadata](https://registry.npmjs.org/eslint-plugin-react/7.37.5), [import plugin metadata](https://registry.npmjs.org/eslint-plugin-import/2.32.0), [Expo preset metadata](https://registry.npmjs.org/eslint-config-expo/58.0.4), [ESLint migration guide](https://eslint.org/docs/latest/use/migrate-to-10.0.0).
