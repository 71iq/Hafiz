# Technology stack specification

Decision date 2026-10-15. Exact installed versions come from package-lock.json. `registry-versions.json` records the npm registry snapshot used for comparison. Latest does not imply compatible.

| Concern              | Chosen implementation and migration rule                                                                                                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework/navigation | Keep Expo SDK 55, React Native 0.83 and Expo Router during stabilization. Align supported patches as a separate task. Assess SDK 56 then 57 with native builds before adopting either. No bare-RN or navigation rewrite.                                                                |
| Language             | Strict TypeScript. Keep the current compatible TypeScript 5.9 line until Expo and analysis tools support a newer major together. Validate boundary data into named domain types. No new any or suppression shortcuts.                                                                   |
| Server state         | TanStack Query v5 for optional remote profile, leaderboard and community data. Use existing service functions. Keep SQLite operations and background sync outside a fake network-query layer.                                                                                           |
| Native UI            | Project-owned components/ui, built on existing RN primitives, rn-primitives/slot and portal. This follows the source-owned React Native Reusables approach. Add an individual compatible primitive only for a demonstrated missing capability. Do not introduce gluestack alongside it. |
| Styling              | NativeWind v4 with existing semantic theme tokens and Tailwind v3. Keep tested RN style objects for measured geometry and platform behavior. No Uniwind migration without measured benefit and a separate compatibility decision.                                                       |
| Icons                | lucide-react-native. Existing callsites already use it. A new icon abstraction or package migration has no current benefit.                                                                                                                                                             |
| Forms                | React Hook Form with Zod for multi-field forms and external validation. Simple toggles and numeric steppers stay local controlled UI. Do not wrap every input in a form framework.                                                                                                      |
| Client state         | Zustand for existing auth/session store. React state for local interaction; existing settings context for persisted settings. Split subscriptions only after profiling or a correctness need.                                                                                           |
| Local data           | Expo SQLite. Bundled Quran data and local personal state remain available offline. No ORM or second local database.                                                                                                                                                                     |
| Optional remote data | Supabase JS through the existing lazy client and domain adapters. SQL migrations are reviewed offline. No deployment or production schema/policy changes in the loop.                                                                                                                   |
| Lists/animation      | Existing FlashList and Reanimated, matched to Expo. Preserve measured index navigation and worklet/native compatibility.                                                                                                                                                                |
| Tests                | Jest with jest-expo and React Native Testing Library for behavior and components; Playwright for the static web app. Add native Maestro flows after an isolated QA build/device exists.                                                                                                 |
| Analysis             | ESLint, Prettier, tsc, Knip, jscpd, dependency-cruiser, npm audit and expo-doctor. Pin new tooling and preserve machine-readable reports.                                                                                                                                               |

## Compatibility research

Expo's current reference lists SDK 55 with RN 0.83 and React 19.2.0, SDK 56 with RN 0.85, and SDK 57 with RN 0.86. The independent latest RN and React releases are not a valid Expo upgrade pair. Use Expo's supported dependency matrix and the SDK upgrade walkthrough for each step. [Expo SDK reference](https://docs.expo.dev/versions/latest/), [upgrade procedure](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/).

The registry snapshot reports Expo 57.0.29, RN 0.87.1, React 19.3.1 and TypeScript 7.0.2 as independent latest releases. It also reports dependency-cruiser 18.6.0 supporting TypeScript below 7. A blanket latest-version update would break the selected compatibility set. These versions are comparison evidence, not approved install targets.

TanStack Query documents React Native support and requires explicit native online/focus integration. Test NetInfo and AppState cleanup, background resumption and account changes before adding those listeners. Do not add another connectivity package because NetInfo already exists. [TanStack React Native guide](https://tanstack.com/query/latest/docs/framework/react/react-native).

NativeWind v4 is the installed stable major; its current site advertises v5 as a release candidate. Uniwind is a maintained alternative, but replacing the existing theme pipeline and CSS interop patch has no demonstrated payoff. [NativeWind installation](https://www.nativewind.dev/docs/getting-started/installation).

React Native Reusables and gluestack both offer native-capable components. Hafiz already owns shared controls and modal behavior, so importing another complete kit would create two systems and put RTL/focus/safe-area behavior at risk. Keep the existing components and extend specific gaps. [React Native Reusables](https://reactnativereusables.com/docs), [gluestack introduction](https://gluestack.io/ui/docs/home/overview/introduction).

See decisions/0001-preserve-expo-and-source-owned-ui.md for the consequential choice. Revisit a choice only with a concrete compatibility, behavior, maintenance or measurement need.
